| 风险 | 概率 | 影响 | 应对措施 |

| russh 库功能不完整 | 中 | 高 | 备选 ssh2-rs，评估后决定 |

## 开发规范

### Git 工作流

```
main ───────────────────────────────────────────── v1.0
  └── develop ──────────────────────────────────── 开发主线
       ├── feature/ssh-connection ──────────────── 功能分支
       ├── feature/sftp-panel
       ├── feature/ai-assistant
       └── fix/terminal-rendering ──────────────── 修复分支
```

- **分支命名**：`feature/功能名` / `fix/问题描述`
- **提交规范**：`feat(ssh): 实现密钥认证` / `fix(terminal): 修复光标闪烁`
- **中文提交**：每次更新代码后中文提交推送到仓库

### 代码审查

- 每个 PR 至少一位 reviewer
- CI 全部通过才能合并
- 敏感代码（加密/安全相关）需两人 review

### 测试策略

| 层级 | 工具 | 覆盖范围 |
|------|------|----------|
| 单元测试 | Vitest + cargo-test | 工具函数、状态管理 |
| 组件测试 | React Testing Library | UI 组件交互 |
| 集成测试 | Playwright | 端到端流程 |
| 性能测试 | cargo-flamegraph | Rust 热路径 |
